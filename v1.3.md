# v1.3 — Release Notes

Released: 2026-11-14

Baseline: v1.2 (`3a93256`)

This release adds the **MVP1 non-digital analytics dashboard**, replaces JWT auth with
**server-side revocable sessions**, adds **filtered Excel exports**, turns the Transaction
Info page into a working **provider lookup**, and refines the history/product UX.

## 1. MVP1 non-digital analytics dashboard

The dashboard at `/dashboard` is rebuilt around the approved analytics mockup
(`frontend/mockups/dashboard-analytics.html`) and covers **non-digital stock only**:
`buy_pulsa`, `buy_data_package`, `package_injection`, `cocktail_sf`. Digital stock
(`stock_transactions`, MVP2) is intentionally excluded.

### What it shows

- **Account strip** — compact Eload and Dompul balances plus a compact API-token card.
  Balance and token refreshes remain independent of analytics refresh.
- **KPI row** — MDA transaction count/day, MDA amount/day with absolute deltas vs the
  previous month, success rate, error rate, transaction amount, transaction count.
- **Daily volume** — stacked success/failed bars on the left `trx` axis, successful
  transaction amount line on the right `Rp` axis, hover-only dot, month-aware x-axis labels,
  and a “Show data” table with totals.
- **MDA by month** — six-month daily average with a Count/day ↔ Amount/day toggle,
  current-month emphasis, elapsed-days note, and a data table exposing both metrics.
- **Brand performance** — per-brand transaction and value shares; bar widths equal the
  displayed share-of-total percentages; SF/XL/AXIS plus any returned brand and `Unknown`.
- **Transaction performance** — all four MVP1 types with total count/amount and a
  Count ↔ Amount brand-composition toggle; direct text labels accompany every color.
- **Top products** — bounded top five for a selected transaction type and brand
  (including `All brands` and `Unknown`); filter changes only reload this panel.
- **Latest transactions** — unchanged local-ledger list with details links and status badges.

### Metric rules

- Source of truth is `local_transactions`; live provider history is never queried.
- **Brand** comes from `products.owner`, outer-joined on both `user_id` and `product_code`.
  Missing product, null/blank owner → `Unknown`. Inactive catalog rows still resolve.
- **Transaction amount** sums recorded `amount` values for `SUCCESS` rows only.
- **Success/error rates** use terminal transactions (`SUCCESS + FAILED`); `PROCESSING` is
  excluded. Rates are 0–1 fractions and are `null` when there are no terminal rows.
- **MDA** is monthly daily average: current month divides by elapsed calendar days,
  closed months by full calendar days. The daily chart is zero-filled across the range.
- **Ranges** are UTC calendar windows: `7d`, `30d`, `90d`, `month` (default `30d`).
- **Top products** group on the transaction snapshot (`transaction_type`, `product_code`,
  `product_name`) plus resolved brand; `display_name` falls back
  name → code → `Unknown product`; ordering is count desc, amount desc, name asc, code asc.

### API

- `GET /api/analytics/non-digital?range=7d|30d|90d|month`
- `GET /api/analytics/non-digital/top-products?range=…&transaction_type=…&brand=…&limit=1..20`

New backend modules: `schemas/analytics.py`, `services/analytics_service.py`,
`api/routes/analytics.py` (mounted under `/api`). Frontend modules live under
`components/dashboard/`, with `useDashboardAnalytics`, `usePrefersReducedMotion`,
and `lib/dashboard.ts`.

### Accessibility and empty states

- Charts include “Show data” tables; color and hover are not the only carriers.
- Count/Amount toggles use `aria-pressed`; chart animations respect
  `prefers-reduced-motion`.
- Loading skeletons, retryable errors, sparse-range notices, and per-panel empty states.
- Daily chart tick density adapts to the range and avoids month-boundary collisions.

## 2. Server-side sessions (replaces JWT)

- New `user_sessions` table + migration **0010**: per-session opaque token hash, user agent,
  IP, `last_seen_at`, absolute `expires_at`, and `revoked_at`.
- `POST /api/login` now creates a session and sets an **HttpOnly, SameSite=Lax** cookie
  (`access_token`) with `secure` configurable. The response returns
  `{ message, username, expires_at }` — **no bearer token**.
- `POST /api/logout` revokes the session server-side and clears the cookie.
- New `GET /api/me` returns the current session info and doubles as the client heartbeat.
- `SessionService` resolves/updates/prunes sessions; `last_seen_at` is throttled to one
  write per minute.
- **Idle timeout: 2 hours. Absolute timeout: 12 hours.** Both can be configured.
- The frontend `useSession` hook validates against `/api/me` (never localStorage), mirrors
  the idle timer, heartbeats while visible and active, handles `auth:expired`, broadcasts
  logout across tabs, and redirects to `/login?expired=1`.
- `DashboardShell` is now guarded by the server-validated session; the old `useAuth` hook
  and JWT utilities are removed.
- New env vars: `SESSION_IDLE_MINUTES`, `SESSION_ABSOLUTE_HOURS`,
  `SESSION_COOKIE_SECURE`, `NEXT_PUBLIC_SESSION_IDLE_MINUTES`.
  Removed: `JWT_ALGORITHM`, `ACCESS_TOKEN_EXPIRE_MINUTES`.

## 3. Excel exports

### Transaction history (server-generated)

- New `GET /api/transactions/local/export` shares the list endpoint’s filters
  (type, status, source, search, start/end date).
- **Filtered-only**: no dump-all path; exports are capped at **20,000 rows**
  (`MAX_EXPORT_ROWS`) and return an actionable 400 when the filter matches more.
- Workbook is written with **openpyxl** in write-only mode to keep memory bounded.
- Columns: Date, Time, Type, Product, Destination, Amount, Status, Source,
  Provider Reference, Local Reference, Payment Method.
- Filenames are filter-descriptive:
  `TransactionHistory_{start}_to_{end}.xlsx`, `_from_`, `_until_`, or `_{today}.xlsx`.
- Response headers include `Content-Disposition` and `X-Export-Row-Count`.

### History UI

- Added a custom **From / To** date range with validation and reset.
- Added an **Export Excel (n)** button showing the current filtered row count; it is
  disabled when the set is empty, invalid, or above the export limit, with inline reasons.
- Exports include **all rows matching the filters**, not just the current page.

### Product catalog (client-generated)

- Eload Product list now has **Export All** and **Export Filtered** buttons.
- Fetches all pages at 100 rows/page, then writes an `.xlsx` with `xlsx` (SheetJS).
- Export columns: Code, Name, Type, Brand, Price, Status, Last Synced.
- Product search now queries code **or** name (`search`), and the table shows **Name first**
  followed by Code.

## 4. Stock Transaction Info lookup

The previously placeholder `/dashboard/stock/transactions` page is now a working,
read-only provider lookup:

- Inputs: family (**XWG / AWG**), operation (**Inject SP / Inject Voucher**), and
  `masterTrxId`.
- Calls the AWG/XWG Info Transaction Detail API and renders aggregated status plus
  per-target rows (MSISDN, status, status detail) and the raw provider response.
- Nothing is persisted; this covers transactions performed outside the dashboard.
- New endpoint: `POST /api/stock/{family}/transaction-info`.
- New schemas: `StockTransactionInfoRequest`, `StockTransactionInfoRow`,
  `StockTransactionInfoResponse`.
- Stock History now lists XWG before AWG.

## 8. Upgrade notes

1. Apply the new migration:
   ```bash

   ```

2. Update `.env`:
   - Add `SESSION_IDLE_MINUTES`, `SESSION_ABSOLUTE_HOURS`, `SESSION_COOKIE_SECURE`,

   section 6.

## 9. Deferred / known limitations

- **Digital stock analytics (MVP2) is not included.** Analytics covers non-digital stock
  only; stock transactions remain in their separate ledger and pages.
- Analytics **composite indexes** are deferred until production data volume justifies them.
  Candidates for a future migration: `(user_id, created_at)`,
  `(user_id, transaction_type, created_at)`, `(user_id, status, created_at)`.
- The default test harness runs portable aggregates on SQLite. Set
  `TEST_DATABASE_URL=postgresql+asyncpg://…` to exercise the Postgres path; `date_trunc`
  behavior is covered by the live EXPLAIN review.
- Visual/responsive and accessibility checks (375/768/1024/1280, keyboard focus,
  reduced motion) remain a manual browser review.
- Product export is client-side and fetches the full catalog page-by-page; it is not
  streamed.

## Breaking changes

- **JWT auth removed.** `/api/login` no longer returns `access_token`; authentication is
  the opaque HttpOnly session cookie plus `GET /api/me`.
- `TokenResponse` is replaced by `SessionInfo`; old JWT settings
  (`JWT_ALGORITHM`, `ACCESS_TOKEN_EXPIRE_MINUTES`) are gone.
- `useAuth` is replaced by `useSession`; the old localStorage username flow is removed.
- Root `/` redirects to `/dashboard` instead of `/login`.
- Product list filtering switched from the `name` UI field to combined `search`
  (code or name), and the product table now leads with Name.
