# v1.2 — Release Notes

Released: 2026-11-02

This release adds **Digital Stock (AWG/XWG)**, **automatic provider history sync**, a more
reliable **transaction verification pipeline**, richer transaction history tooling, and a
full UI/UX refresh.

---

## Highlights

| Area | What's new |
| --- | --- |
| Digital Stock | Browse AWG/XWG voucher stock, inject vouchers to one or many MSISDNs, and track it in a dedicated stock history. |
| History auto-sync | Pull the provider's transaction history into the local ledger on a schedule (15 min → 24 h) or on demand. |
| Verification | Post-submit retries + a background re-check loop keep async transactions accurate; inconclusive results stay `PROCESSING` instead of being marked failed. |
| History UX | Faceted status summary, full-text search, source filter, copyable references, mobile card layout, unmasked debug data + cURL. |
| Config UX | Grouped, searchable credential cards with a readiness meter and a transaction PIN card. |
| Design | New design-token system, redesigned login, refreshed sidebar navigation, status badges with dots. |

## 1. Digital Stock (AWG / XWG)

### Stock browser
- New **Digital Stock** page (`/dashboard/stock`) with an AWG/XWG switch.
- XWG supports a configurable `roType` query parameter (default `MINI-GROSIR`).
- Shows per-voucher rows: code, description, price, stock balance, effective/expiry
  dates, `allowType`, and `vID` (copyable).
- Summary bar with total stock lines, total vouchers, and total stock value (price × balance).
- Client-side search by voucher code or description; responsive table/card layouts.
- Credentials-missing errors link directly to API Config.

### Stock injection
- **Inject** action per stock row opens a dialog supporting **multiple target MSISDNs**
  (one per line or comma-separated).
- Uses the transaction PIN (stored encrypted) and the provider's inject endpoint.
- Records the operation in the new stock ledger as `PROCESSING`, then resolves status via
  the family's Info Transaction Detail API with a short in-request retry window.
- New endpoint: `POST /api/transactions/stock-inject`.
- New service: `StockInjectService` with per-family commands
  (`awg: tembak-paket-ir`, `xwg: sell-voucher`).

### Stock history
- New **Stock History** page (`/dashboard/stock/history`) listing injections recorded by
  this system — kept separate from non-stock transaction history.
- Filters: family, service type, status facet chips, search (description / voucher code /
  masterTrxId / destination), and date range (today / 7d / 30d).
- Paginated, with status counts computed as a facet (counts stay accurate while a status
  filter is applied).
- **Re-check** action per row and a fully detailed record view
  (`/dashboard/stock/history/{family}/{id}`) with per-target detail rows
  (MSISDN, status, status detail) and an unmasked-data toggle.
- Service type labels for `SELLVOUCHER`, `PHYSICALVOUCHER`, `TRANSFER`, `BUYSTOCK`,
  `EXTENDSTOCK`, `TRFBALANCE`, `TEMBAKSTOK`.
- New endpoint group: `GET /api/stock/{family}/history`,
  `GET /api/stock/{family}/history/{id}`,
  `POST /api/stock/{family}/history/{id}/refresh-detail`.

### Stock APIs & data
- New `GET /api/stock/{family}` endpoint returning normalized stock items plus totals.
- New tables/model: `stock_transactions` (digital stock ledger) and the supporting
  schemas (`StockItemOut`, `StockListResponse`, `StockHistoryItem`,
  `StockHistoryDetailOut`, `StockHistorySummary`).
- Provider configuration added for:
  - `get-awg-stock`, `get-xwg-stock`
  - `post-awg-tembak`, `post-xwg-tembak`
  - `post-awg-transaction-info-detail`, `post-xwg-transaction-info-detail`
- New credential types: `awg`, `xwg`, `awg_stock_inject`, `xwg_stock_inject`,
  `awg_transaction_info_detail`, `xwg_transaction_info_detail`.
- **Transaction Info** placeholder page (`/dashboard/stock/transactions`) documenting the
  pending provider spec for Get Info Transaction.

> Note: the provider no longer exposes stock transaction-list endpoints, so stock history
> is system-generated and verified through Info Transaction Detail only. Migration `0009`
> drops the now-unused `stock_sync_settings` table.

## 2. Provider history auto-sync

- New per-user sync configuration stored in `user_sync_settings`.
- Endpoints:
  - `GET /api/profile/sync-settings`
  - `PUT /api/profile/sync-settings` (enable/disable, interval)
  - `POST /api/profile/sync-settings/run-now`
- Supported intervals: **15 minutes, 1 hour, 6 hours, 24 hours**.
- `HistorySyncService` pulls the provider history into `local_transactions` with
  `source="synced"`, de-duplicating against known provider/local references and re-reading
  a 1-day overlap so late-arriving rows are not missed.
- Records provider-reported status using the shared status classifier and persists both
  masked and unmasked raw responses.
- A background loop runs every 60 seconds and syncs only users whose interval has elapsed,
  one user at a time so one account cannot block or rate-limit another.
- The History page shows an **Auto-sync provider history** card: on/off, interval,
  last sync time/status/count, next sync time, last error, **Sync now**, and a note that
  the provider only returns its latest ~2,500 transactions (local persistence extends this).
- Synced rows display a **synced** badge in the history list.

## 3. Transaction verification improvements

- New shared `classify_provider_status()` maps provider status text (English and Indonesian:
  `SUCCESS`, `SUKSES`, `BERHASIL`, `DONE`, `FAILED`, `GAGAL`, `CANCELLED`, `REVERSED`,
  `PROCESSING`, `SEDANG DI PROSES`, …) to local statuses.
- **Inconclusive results no longer become `FAILED`.** If the provider has not reported yet,
  the record stays `PROCESSING` for later re-checks.
- Async flows (`buy_data_package`, `package_injection`) now verify immediately after submit
  with a short retry window (3 attempts over ~15 s).
- A background re-check loop runs every 60 seconds over:
  - records still `PROCESSING`, and
  - recent `FAILED` records (7-day look-back) so mis-classified rows can self-heal.
- Same treatment for stock transactions via the Info Transaction Detail API.
- Manual **Re-check** is available from the history list for async types, and
  **Refresh Status** is available on the detail page at any time (not only when processing).
- Verification backfills `product_name`, `product_code`, and `amount` from the detail row
  and stores the raw detail under `check_history_detail`.

## 4. Transaction history overhaul

- Local history list (`/dashboard/history`) rebuilt with:
  - Status facet chips (All / Success / Failed / Processing) with counts from the whole
    filtered set — counts stay accurate while a status filter is active.
  - Summary including `success_amount` (total value of successful transactions).
  - Full-text search across transaction/provider refs, destination, product name/code.
  - New `source` filter (`app` vs `synced`).
  - Copyable provider/local references, relative timestamps, human-readable type labels.
  - Responsive card layout for small screens; skeleton loading states.
- Transaction detail (`/dashboard/history/{id}`):
  - **Show unmasked data** toggle for raw request/response debug payloads.
  - One-click **cURL** snippet of the recorded request.
  - Refresh status available for async flows at any time.
- `Latest Transactions` on the dashboard now reads from the local ledger (always current)
  instead of the provider list, with refresh support.

## 5. Unmasked debug data

- New `local_transactions` columns: `metadata_unmasked`, `raw_response_unmasked`
  (migration `0006`).
- Transaction services now store the actual (unmasked) request URL/body and raw response
  alongside the existing masked copies used for display.
- The request body never contains the plaintext PIN — only the provider-encrypted PIN.

## 6. Credentials & configuration

- API Config page redesigned (`/dashboard/config`):
  - Credential cards **grouped by category**: Authentication, Balances, Products & history,
    Transactions, Digital Stock.
  - **Readiness meter**: configured vs. missing count and percentage.
  - Search by label/API name plus filters (All / Configured / Needs setup).
  - Per-card status chips, inline validation, show/hide secret, "encrypted at rest" notice.
  - New **Transaction PIN** card to set/change the PIN (stored encrypted, never returned).
- Credential registry updates:
  - Added `history_detail`, `awg`, `xwg`, `awg_stock_inject`, `xwg_stock_inject`,
    `awg_transaction_info_detail`, `xwg_transaction_info_detail`.
  - Removed `balance_pulsa` (Pulsa balance is no longer a provider balance type).

## 8. Backend, migrations & infrastructure

- Migrations:
  - `0006` — unmasked debug columns on `local_transactions`.
  - `0007` — history auto-sync (`source`, `provider_transaction_id`, `synced_at`,
    `user_sync_settings`).
  - `0008` — digital stock (`stock_transactions`, `stock_sync_settings`).
  - `0009` — drop `stock_sync_settings`.
- New routers: `stock`, `stock_history`; new services: `stock_service`,
  `stock_history_service`, `history_sync_service`, `stock_inject`.
- Startup now launches two background tasks: transaction/stock re-check loop and
  provider history sync loop.
- Provider client's `_build_url` is now public `build_url` (used for debug cURL/endpoint
  capture).
- Provider config: history detail endpoint corrected to
  `/get-transaction-history-detail`; removed `provider_balance_pulsa_*` settings.
- Added `history_detail` credential usage with fallback to `history_api` for backward
  compatibility.

## Breaking changes

- **Pulsa balance removed** from the API responses, schemas, UI, and credential list
  (`BalanceSummary` now has only `eload` and `dompul`). Update any external consumers of
  `/api/balance` accordingly.
- Provider history detail endpoint is now `/get-transaction-history-detail` (previously
  `/get-transaction-historydetail`).
